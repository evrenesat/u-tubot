# Cut model choice, measured 2026-11-20

The `[llm.cuts]` model is picked with the offline test set (`utubot/cutbench.py`: five
hand-marked transcripts x three requests, must-keep/must-skip spans, an excess-keeping budget
at 1.5x the marked keep time; no YouTube, one chat call per request). This file records the
measurement (`scores-2026-11-20.json` is the full run document) so the next re-run can compare.

Scoring: `keep` = share of the marked must-keep time the finished cut covers; `skip` = 1 minus
the share of marked must-skip time that leaked into the cut; `excess` = how much the cut
over-keeps against the request's budget (share of the video); `score` = keep - (1 - skip) - excess.

| alias | score | keep | skip | excess | refusals | format errors | s/req |
|---|---|---|---|---|---|---|---|
| fast | +0.849 | 1.000 | 0.932 | 0.083 | 0 | 0 | 7.0 |
| fast-instruct | +0.836 | 1.000 | 0.922 | 0.087 | 0 | 0 | 6.1 |
| heavy-alt | +0.822 | 1.000 | 0.910 | 0.088 | 0 | 0 | 47.4 |
| light | +0.822 | 0.997 | 0.914 | 0.089 | 0 | 0 | 37.8 |
| fast-legacy | +0.817 | 1.000 | 0.909 | 0.092 | 0 | 0 | 6.1 |
| heavy | +0.793 | 1.000 | 0.874 | 0.080 | 0 | 0 | 24.9 |

**Pick: `fast`** — the best score on the set, every request answered in valid JSON on the first
try, and fast enough that a cut feels live. `fast-instruct` is the natural fallback (nearly the
same score, the same speed); the heavy aliases think for half a minute or more per request
without scoring better, and `light` burns twice the output tokens for the same result.

Notes on the set, read before re-running:

- The transcripts are short (~2.5 min each, ~34 units) so the whole set runs in minutes; the
  unit-merging and marking behaviour is what separates models here, not token budgets. A set
  with 10-30 minute transcripts is worth adding before the next pick if two aliases tie.
- The sourdough `no-filler` marking is the harshest one: its gear list reads like substance and
  every alias keeps part of it (that leak is the biggest single skip loss in the table). Treat
  the sourdough `no-filler` `skip` column as a known-hard cell, not a model defect.
- The aliases measured are the gateway's at measurement time (the deploy config names the alias
  to serve as `[llm.cuts].model`); re-run `scripts/cut_bench.py` against the live list when the
  gateway changes.
